Task Tracker

Connect your AI

Connect AI assistants to your tasks via an optional sync server.

Task Tracker can let AI assistants like Claude, Cursor, other MCP apps, and n8n read and update your tasks. This is optional and works only through a sync server you run and control—nothing goes to us. For full details, read our privacy policy.

Step 1 – Run your sync server

You need Docker installed. Clone the repo and set up the server: 

git clone https://github.com/rshukla2/TaskTracker.git
cd TaskTracker/server
cp .env.example .env

Set SYNC_KEY to a random 32+ character string: 

openssl rand -hex 32

Then start the server: 

docker compose up -d

Note: The provided docker-compose.yml joins an external network named n8n_default. If you don't use that, remove the networks section and add ports: 

ports:
  - '8787:8787'

To use it from your phone, put it behind HTTPS (for example with Caddy). Check it works: 

curl https://your-server/health

It should return {"status":"ok", ...}.

For quick testing on a Mac: ./run-local.sh (prints URL + key).

Step 2 – Connect the app

In the Task Tracker app: Settings > Sync (optional) > enter your Server URL and Sync Key > tap Test connection > turn on Enable sync.

Step 3 – Connect your AI

The MCP server package is @rishishukla2k/task-tracker-mcp (needs Node 20+). Set environment variables TASKTRACKER_URL and TASKTRACKER_KEY.

Claude Code

claude mcp add tasktracker -e TASKTRACKER_URL=https://your-server -e TASKTRACKER_KEY=your-key -- npx -y @rishishukla2k/task-tracker-mcp

Claude Desktop

Settings > Developer > Edit Config. Add to claude_desktop_config.json: 

{
  "mcpServers": {
    "tasktracker": {
      "command": "npx",
      "args": ["-y", "@rishishukla2k/task-tracker-mcp"],
      "env": {
        "TASKTRACKER_URL": "https://your-server",
        "TASKTRACKER_KEY": "your-key"
      }
    }
  }
}

Restart Claude Desktop after editing.

Cursor and other MCP apps

Same JSON in their MCP config (Cursor: ~/.cursor/mcp.json).

n8n or any script

Call the HTTP API directly with header Authorization: Bearer <key>: 

curl -H 'Authorization: Bearer your-key' 'https://your-server/api/tasks?completed=false'

What your AI can do

Once connected, your AI gets these tools:

Read tools

Tool Description
list_statuses List the task statuses (default and custom).
list_work_cycles List your work cycles.
list_sprints List the sprints in a work cycle.
list_tasks List tasks, filtered by status, cycle, sprint, done or due date.
get_task Get one task by its ID.
changes_since See what changed since a given time.

Tasks

Tool Description
create_task Create a task in a sprint (title, description, deadline, estimated hours, effort, status, blocker reason).
update_task Update any task field (title, description, deadline, hours, effort, status, blocker reason, sprint). All fields except title are optional; set to null to clear.
complete_task Mark a task as completed.
reopen_task Reopen a completed task.
move_task_to_next_sprint Move a task to the next sprint and set its deadline to that sprint's start date.
delete_task Delete a task (it syncs as deleted on your devices).

Work cycles

Tool Description
create_work_cycle Create a work cycle with one or more initial sprints.
update_work_cycle Update a work cycle's name, description or end goal (dates are derived from sprints).

Sprints

Tool Description
create_sprint Add a sprint to a work cycle (specify length or end date; optionally insert after another sprint).
update_sprint Update a sprint's name, end goal or dates.
resize_sprints Re-split a work cycle's sprints to a new length (creates more sprints to reach the same end date, or extends the cycle).

How dates work

Sprints are always back to back: each sprint starts the day after the previous one ends. Work cycle dates are derived from their sprints and cannot be set directly.

  • Adding a sprint shifts all later sprints later by the new sprint's length; cycle end grows.
  • Shrinking a sprint shifts later sprints earlier; cycle end shrinks.
  • Resizing to shorter creates more sprints to keep the cycle end; resizing to longer extends the cycle.
  • Default names (Sprint 1, Sprint 2, etc.) are renumbered when a sprint is inserted.
  • Task deadlines are never moved automatically; use move_task_to_next_sprint to set a deadline to the next sprint's start date.
  • No deletes for work cycles or sprints.

Example prompts

  • "What is due this week?"
  • "Add a task "Email the landlord" to my current sprint"
  • "Mark the dentist task done"
  • "Create a 6-week work cycle called Launch with three 2-week sprints starting Dec 1"
  • "Make every sprint in Launch 5 days long"
  • "Add a 1-week buffer sprint after Sprint 2"
  • "Move my unfinished tasks in Sprint 3 to the next sprint"

Keep your key safe

Anyone with your sync key can read and change your tasks. Rotate it by changing SYNC_KEY in your server's .env and restarting, then update the app and AI config with the new key.
